# Architecture & Design Decisions

## 2026-09-25

### Decision 001 — Premium B2B positioning
RCS should visually communicate reliability, operational capability and professionalism rather than look like a generic local transport website.

### Decision 002 — Official logo
The supplied logo is the source of truth. Do not redesign it. The original file is kept in `public/brand/source/`.

### Decision 003 — Founder on homepage
Satya Swain has a dedicated founder section on the homepage to add human trust and company identity.

### Decision 004 — Conversion goal
Primary conversion: quote request. Secondary: WhatsApp "Talk to our team".

### Decision 005 — Animation (revised)
Motion only. GSAP removed from the initial build: the planned interactions don't need it and it adds bundle weight. Revisit only if a specific interaction genuinely requires it.

### Decision 006 — Full-stack foundation
Next.js, so the marketing site can grow into a lead-management/application platform without a rewrite.

### Decision 007 — Accessible orange
`#FF6B00` with white text measures 2.86:1 and fails WCAG AA. Split into `brand-orange #FF6B00` (accents, icons, never behind white text) and `action-orange #B84D00` (buttons with white text, 5.12:1; orange links). Hover `#9A4000` (6.76:1).

### Decision 008 — Navy matched to logo
Navy token changed from `#071B2B` to `#0F2026`, sampled from the logo wordmark, so the navbar and headings match the logo. Pending client confirmation of official brand colours.

### Decision 009 — Logo assets
Client file was a 1774×887 RGB PNG with an off-white background and ~60% padding. Created `rcs-logo.png` (trimmed, transparent, colour-to-alpha so edges stay smooth — shapes and colours unchanged) and `rcs-mark.png` (the "R" mark cropped, 512×512). No reversed/white logo is created; dark surfaces use the mark + text or the logo on a white panel. Replace with client SVGs when supplied.

### Decision 010 — No invented facts; placeholders + feature flags
All company facts centralised in `lib/site-config.ts`. Unconfirmed values use `[[TBC: ...]]`; sections dependent on unconfirmed data are hidden behind feature flags. Metrics strip replaced by a non-numeric capability strip until numbers are verified.

### Decision 011 — Founder presentation
Designation shows "Founder" until confirmed ("Managing Director" only applies if the entity is a company). No portrait placeholder photo of a stranger; no simulated signature.

### Decision 012 — Privacy & spam
DPDP Act 2023: explicit unticked consent checkbox, Privacy Policy and Terms pages, data minimisation, hashed IPs only. Spam: Cloudflare Turnstile + honeypot + Postgres-backed rate limit (5/IP/hour).

### Decision 013 — Quote form fields
Added optional approximate load, vehicle type and preferred pickup date — the first questions an ops team asks when quoting. Service type is a fixed enum matching the four services + "Other".

### Decision 014 — Naming
"Part Truck Load (PTL)" everywhere; route renamed `/services/part-load` → `/services/part-truck-load`.

### Decision 015 — Typography
Archivo (variable weight + width). Expanded width for headings echoes the wide RCS wordmark; normal width for body. One family keeps the system disciplined.

### Decision 016 — Library versions (Phase 1)
Next.js 16.3.6 (App Router, Turbopack default) · React 19.2.8 · TypeScript 5.9.3 (strict) · Tailwind CSS 4.3.3 (CSS-first `@theme` in `app/globals.css`, no `tailwind.config`) · ESLint 9.39 (flat config, `eslint` CLI — `next lint` no longer exists in 16) · shadcn CLI 4.21.0 (`radix-nova` style, `radix-ui` 1.6.7, `cn` 0.4.0 — shadcn's own clsx + tailwind-merge replacement) · lucide-react 1.48.0 · motion 13.4.3 · react-hook-form 7.88.0 · zod 4.6.5 · @hookform/resolvers 5.9.1. Node 24.
Prisma, Resend and Turnstile are deferred to the quote-form phase.

### Decision 017 — Next.js 16 specifics
- `next/image` `priority` is deprecated in 16; above-the-fold images use `loading="eager"` (or `preload` for a true LCP image such as the hero photo).
- `LayoutProps`/`PageProps` are global types generated by `next build`/`next dev` typegen.
- `AGENTS.md` (written by create-next-app) is referenced from `CLAUDE.md`: read the bundled docs in `node_modules/next/dist/docs/` before using a Next API.

### Decision 018 — Light-only theme; shadcn variables mapped to brand
The design system defines no dark theme, so the shadcn dark palette was removed. shadcn's semantic variables (`--primary`, `--ring`, …) are mapped onto brand tokens so added shadcn components inherit the brand. Button rewritten to the two design-system variants (`default` = action-orange, `secondary` = navy outline) plus `link`, and `ghost` for icon-only controls; minimum height 48px (40px `sm` in the navbar).
Two tokens not in the design system were added, both measured:
- `--destructive #B42318` for error text — 6.57:1 on white, 6.12:1 on surface.
- `--input #868E9C` for input borders — 3.30:1 on white, 3.07:1 on surface (WCAG 1.4.11 non-text ≥ 3:1). `border #E5E7EB` stays for dividers/cards only, as it is too light for form controls.

### Decision 019 — Navigation pattern
Desktop "Services" uses the disclosure pattern (button with `aria-expanded` + list of links; Esc returns focus, click-outside and focus-out close) instead of an ARIA menu, which is the recommended pattern for site navigation. Mobile uses a full-width shadcn Sheet (Radix Dialog: focus trap, Esc, focus return). A "Skip to content" link precedes the navbar.

### Decision 020 — Placeholder display
`isConfirmed()` treats `[[TBC…` and empty strings as unconfirmed. `shouldDisplay()` shows placeholders in development (so gaps are visible while building) and hides them in production builds. Placeholder contact values are never turned into `tel:`/`mailto:` links. The footer copyright falls back to the brand name in production until the legal name is confirmed.

### Decision 021 — Logo alt text in the dark-surface lockup
The footer lockup pairs `rcs-mark.png` with the brand name in live text; the mark there uses `alt=""` because screen readers would otherwise read "RCS Logistic Solutions" twice. The link wrapping it carries the accessible name. All standalone logo images use alt "RCS Logistic Solutions".

### Decision 022 — Favicon
`app/icon.png` is a copy of `public/brand/rcs-mark.png` (transparent). No `apple-icon` yet — iOS renders transparency as black; generate one on a white background alongside the OG image in the SEO phase.

## 2026-09-25 (Phase 2+)

### Decision 023 — Photography placeholders
The design plan was approved without a photo source being chosen. All photos are fed from `content/media.ts`. While `src` is `null`, a neutral hatched frame renders; in development it also shows the photo brief. Adding a real or licensed image is a one-line change per slot. No stock images were downloaded or hot-linked.

### Decision 024 — Hero entrance uses CSS, route line uses Motion
The hero sequence is a CSS keyframe (`animate-rise`, staggered delays, ≤ 800ms), so it needs no client JS and doesn't delay LCP. The "How it works" route line is the only Motion component. It uses a `clip-path` reveal so one animation works both horizontally (desktop) and vertically (mobile). The in-view trigger sits on an unclipped wrapper, because a fully clipped element never reports as intersecting. Reduced motion renders the line fully drawn.

### Decision 025 — Service pages
The four routes are explicit folders, per architecture.md, each rendering the shared `components/services/service-page.tsx` template. Page copy (intro, "Who it's for", steps) lives in `content/services.ts`. It describes the service type only, with no capacity, coverage, transit-time or vehicle claims. Quote links use `?service=ftl|ptl|warehousing|supply-chain`, which pre-selects the form.

### Decision 026 — Prisma 7 + Neon adapter
Prisma **7.10.0** was pinned (npm `latest` currently points at an 8.0 release candidate). Setup uses:
- the new `prisma-client` generator with output at `lib/generated/prisma` (gitignored; `postinstall` runs `prisma generate`);
- `prisma.config.ts` for the CLI datasource: `DIRECT_URL`, falling back to `DATABASE_URL`. It loads `.env.local` and `.env` because the Prisma CLI does not;
- at runtime, `@prisma/adapter-neon` over the pooled `DATABASE_URL`. Node 24 has a global WebSocket, so there's no `ws` dependency.

The initial migration SQL (`prisma/migrations/20260925000000_init`) was generated offline with `prisma migrate diff`. Apply it with `npm run db:deploy`.

### Decision 027 — Environment validation
`lib/env.ts` (server-only, Zod) validates lazily on first use and lists every missing variable at once. `instrumentation.ts` checks at server start. It **throws** on Vercel production or when `REQUIRE_SERVER_ENV=true`, and otherwise warns, so the marketing pages stay usable in development and previews while the forms return a clear error.

### Decision 028 — Form behaviour
- Server actions take the typed object (not `FormData`) and re-validate it with the same Zod schema.
- RHF's built-in error focus was replaced with `focusFirstInvalid()`, which walks `form.elements` in DOM order: RHF focused the consent checkbox before earlier fields.
- If a Turnstile site key is configured but there's no token yet, the client blocks the submit with a message. The server always requires a valid token.
- For local development, `.env.local` (gitignored) holds Cloudflare's public always-pass test keys. They are documented in `.env.example`.
- The notification email sets `replyTo` to the enquirer, so the team can answer directly. Submitter data only goes to `QUOTE_NOTIFICATION_EMAIL`.

### Decision 029 — Legal drafts and SEO
- `/privacy-policy` and `/terms` render `[[TBC]]` values verbatim, so gaps are obvious. They carry the draft notice, are `noindex`, and are left out of the sitemap until approved.
- The privacy draft names the actual processors: Vercel (hosting and cookie-free Analytics), Neon, Resend and Cloudflare Turnstile.
- The OG image is generated from the unaltered logo on white, with an orange baseline rule. `apple-icon` is the R mark on a white tile.
- JSON-LD: `Organization` is sitewide and each service page has `Service`; both drop `[[TBC]]` values. There's no `LocalBusiness` until an address is verified.

### Decision 030 — Performance adjustments from the first Lighthouse pass
- The route line uses `LazyMotion` + `m` with `domAnimation` instead of the full `motion` component, which removed a ~119 KB chunk.
- The hero H1 renders immediately, with no opacity animation, so it is visible on the first frame and counts as the LCP element. The supporting line, image and CTAs still rise in sequence.
- Local mobile Lighthouse (headless Edge on the dev machine, `next start`): Accessibility 100, SEO 100 (with `NEXT_PUBLIC_SITE_URL` set), Best Practices 96 (the only failure is the Vercel Analytics script 404ing outside Vercel), Performance 64–69.
- On this machine, observed first paint was ~2.3s even for a fully loaded page, while a bare HTML baseline painted in 0.27s. The cause wasn't isolated. **Re-measure Performance on the Vercel preview (PageSpeed Insights) before tuning further**; the ≥ 90 target is not yet verified.
